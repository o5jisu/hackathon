# 포즈메이트 (가칭)

> 참고 사진의 포즈를 따라 촬영하도록 돕고, 촬영한 사진의 색감을 참고 사진에 맞춰 주는 AI 포즈 코칭 서비스입니다.
>
> **팀 해커톤 기획안** · 24시간 MVP 기준  
> 서비스명과 기술 구성은 확정 전이며, 아래에 제안으로 표시한 항목은 구현 과정에서 조정할 수 있습니다.

## 프로젝트 개요

혼자 사진을 찍을 때 포즈를 어떻게 취해야 할지 몰라 여러 번 촬영하거나, 참고 사진과 비슷한 자세를 만들기 어려운 경우가 많습니다. 포즈메이트는 참고 포즈를 카메라 화면에 겹쳐 보여주고, 사용자의 자세가 맞춰지는 정도를 색과 쉬운 문장으로 안내합니다. 촬영이 끝나면 결과 사진에 간단한 색감 보정도 적용할 수 있습니다.

### 문제와 해결

| 사용자의 어려움 | 포즈메이트의 해결 |
| --- | --- |
| 포즈를 기억하거나 따라 하기 어렵다 | 사용자가 올린 참고 사진을 흐릿하고 반투명하게 카메라 화면에 겹쳐 표시 |
| 관절 각도 숫자는 이해하기 어렵다 | “오른쪽 팔을 조금 더 들어 보세요”처럼 자연어로 안내 |
| 자세가 맞는지 촬영 전에 알기 어렵다 | 참고 포즈와 현재 포즈의 관절을 초록색·빨간색으로 구분 |
| 참고 사진과 촬영 결과의 분위기가 다르다 | 촬영한 사진의 전체 색감을 참고 사진에 가깝게 보정 |

## 핵심 사용자 흐름

1. **참고 사진 업로드** — 사용자가 따라 하고 싶은 사진을 기기에서 선택해 올립니다.
2. **카메라 정렬** — 업로드한 참고 사진을 흐릿하고 반투명하게 카메라 화면에 겹쳐 표시합니다.
3. **포즈 코칭** — 카메라 영상에서 추정한 관절 위치를 기준과 비교합니다. 기준에 가까운 관절은 초록색, 차이가 큰 관절은 빨간색으로 보여줍니다.
4. **쉬운 수정 안내** — 숫자 각도 대신 “왼쪽 어깨를 조금 내리고, 오른손을 얼굴 옆으로 가져가 보세요”처럼 바꿀 동작을 안내합니다.
5. **촬영 및 색감 맞추기** — 포즈가 맞춰지면 사진을 촬영하고, 업로드한 참고 사진의 색감을 촬영 결과에 적용해 저장하거나 공유합니다.

## 포즈 가이드 디자인

- **기준 자세:** 사용자가 올린 참고 사진을 흐릿하고 반투명하게 카메라 화면 위에 겹쳐 보여줍니다. 투명도와 흐림 정도를 조절할 수 있게 할지는 **제안 사항**입니다.
- **현재 자세:** 사용자의 추정 관절을 기준 자세와 비교해 표시합니다.
- **일치한 관절:** 초록색으로 표시합니다.
- **차이가 큰 관절:** 빨간색으로 표시합니다.
- **각도 숫자:** 사용자에게 각도 값을 직접 노출하지 않습니다. 화면의 색상과 짧고 직관적인 설명으로 다음 행동을 안내합니다.

색상 판정 기준과 허용 범위는 **제안 사항**입니다. MVP에서는 화면 크기와 사용자 위치에 영향을 덜 받도록 정규화한 관절 좌표 간 거리를 활용하고, 몇 개의 핵심 관절부터 비교하는 방식을 검토합니다.

## 촬영 후 색감 보정

촬영이 끝나면 업로드한 참고 사진의 색감 특징을 추정해 내가 찍은 사진에 적용합니다. 사용자는 보정 전·후를 비교하고, 보정 강도를 조절하거나 원본으로 되돌릴 수 있습니다. 포즈 코칭과 색감 처리는 별도 단계로 두며, 원본 사진은 보존합니다.

**MVP 구현 제안:** Canvas 2D로 두 이미지의 밝기, 색상 채널별 평균, 채도 같은 간단한 통계를 비교하고 촬영 사진에 보정값을 적용합니다. 이는 전체적인 따뜻함·차가움과 밝기 분위기를 근사하는 방식이며, 두 사진의 조명·배경·피부색이 달라도 완전히 동일한 색으로 만드는 것은 보장하지 않습니다. 장면별 보정이나 인물·배경 분리는 MVP 범위에서 제외합니다.

## 선택 확장: 셀카 포즈 코칭

후속 확장으로 셀카에 맞춘 상반신 포즈 가이드를 고려할 수 있습니다. 얼굴 방향이나 어깨 방향을 활용해 시선과 상체를 안내하는 방식입니다. 다만 24시간 MVP에서는 기본 전신 또는 상반신 포즈 맞추기와 촬영 흐름을 우선 완성하고, 셀카 전용 동작은 시간과 모델 성능을 확인한 뒤 범위를 정합니다.

## 권장 API·오픈소스 구성안

24시간 MVP는 **브라우저에서 동작하는 웹 앱**으로 먼저 만드는 구성을 권장합니다. 별도의 서버나 유료 생성형 AI API를 붙이지 않고, 포즈 추정은 MediaPipe 오픈소스 라이브러리, 사진 오버레이·보정은 브라우저 기본 기능, 안내 문구는 규칙 기반 로직으로 구현합니다. 이 구성은 **기술 제안**이며 팀의 배포 환경과 숙련도에 따라 바꿀 수 있습니다.

| 구분 | 권장 선택 | MVP에서의 용도 |
| --- | --- | --- |
| 웹 앱 | React + Vite *(팀이 이미 익숙한 프레임워크가 있으면 대체 가능)* | 업로드, 카메라, 코칭, 결과 화면을 빠르게 구성 |
| 포즈 라이브러리 | [`@mediapipe/tasks-vision`](https://www.npmjs.com/package/@mediapipe/tasks-vision) | 브라우저에서 Pose Landmarker 사용 |
| 기준 사진 분석 | MediaPipe Pose Landmarker의 이미지 모드 `detect()` | 업로드 사진의 신체 랜드마크 추정 |
| 실시간 카메라 분석 | MediaPipe Pose Landmarker의 비디오 모드 `detectForVideo()` | 카메라 프레임별 현재 자세 추정 |
| 카메라 접근 | 브라우저 `getUserMedia()` API | 사용자가 허용한 경우 카메라 스트림 표시 |
| 사진 오버레이·색감 | HTML/CSS 및 Canvas 2D API | 흐림·투명도 오버레이, 참고 사진 색감의 간단한 추정·적용 |
| 코칭 문장 | 앱 내부 규칙 기반 텍스트 | 차이가 큰 관절에 대응하는 짧은 문장 표시 |
| 얼굴 분석 | 이번 MVP에서는 사용하지 않음 | Face Landmarker는 셀카 확장 단계에서 검토 |

MediaPipe 웹 Pose Landmarker는 이미지 입력과 비디오 입력을 지원하며, 이미지에는 `detect()`, 영상 프레임에는 `detectForVideo()`를 사용하는 흐름을 문서에서 안내합니다. 프레임 추론 호출은 메인 UI 스레드를 막을 수 있으므로, 우선 낮은 처리 빈도로 구현하고 끊김이 보일 때 Web Worker로 옮기는 것이 현실적인 순서입니다. [공식 Web 가이드](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)

### 이 조합에서 실제로 처리되는 흐름

1. 사용자가 참고 사진을 업로드합니다. 사진은 브라우저에서 Pose Landmarker 이미지 모드로 분석합니다.
2. 분석한 참고 포즈 데이터는 코칭 화면에서 쓸 수 있도록 임시 메모리에 보관합니다.
3. 사용자가 카메라 권한을 허용하면 `getUserMedia()`로 실시간 영상을 표시하고, Pose Landmarker 비디오 모드로 사람의 관절을 추정합니다.
4. 두 랜드마크 집합을 비교해 차이가 큰 관절을 찾고, 현재 카메라 영상 위에 초록색·빨간색 점이나 선으로 표시합니다.
5. 참고 사진은 카메라 위에 별도 이미지 레이어로 겹칩니다. 투명도와 흐림은 CSS로 조절하고, 사진의 크기·위치 정렬은 사용자가 조절할 수 있게 하는 방안을 권장합니다.
6. 안내 문장은 관절 비교 결과에 따라 미리 준비한 문구 중에서 선택합니다. 외부 LLM API 호출은 MVP에 포함하지 않습니다.
7. 촬영 후에는 Canvas 2D로 참고 사진과 결과 사진의 간단한 색상 통계를 비교해 밝기·색온도·채도 보정값을 적용합니다. 보정 강도 조절과 원본 비교를 제공합니다. 브라우저별 이미지 처리 성능은 시연 기기에서 확인합니다.

MediaPipe의 랜드마크 출력에는 정규화 좌표와 가시성 정보가 포함되므로, 참고 사진과 카메라 화면의 방향·크기를 정렬하고 신뢰도가 낮은 관절을 안내에서 제외하는 데 활용할 수 있습니다. [랜드마크 결과 문서](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)

### 설치·모델 준비 제안

```bash
npm install @mediapipe/tasks-vision
```

MediaPipe 가이드에 따라 호환되는 Pose Landmarker 모델 파일을 프로젝트에 포함하거나 정적 파일로 제공해야 합니다. 해커톤에서는 모델을 미리 내려받아 저장소 또는 배포 정적 경로에서 로드하는 편이 시연 중 네트워크 변수에 덜 의존합니다. 모델의 정확도·용량 선택은 먼저 대표 참고 사진과 목표 기기에서 확인한 뒤 확정합니다.

### 범위와 기술상 주의점

- 참고 사진 분석과 실시간 분석이 모두 된다고 해서 두 사람이 자동으로 같은 크기와 위치에 정렬되는 것은 아닙니다. MVP는 사용자가 카메라 앞에서 몸의 크기와 위치를 맞추도록 안내하고, 비교 대상 관절 수를 제한합니다.
- 참고 사진에 사람이 여러 명 있거나 몸 일부가 잘렸거나 가려진 경우를 자동으로 해결하는 기능은 MVP에서 보장하지 않습니다. 한 명의 전신 또는 상반신이 잘 보이는 사진을 데모 입력으로 준비합니다.
- 좌우 반전 카메라에서는 좌우 관절 이름과 화면 방향이 헷갈릴 수 있습니다. 사진과 영상 중 무엇을 좌우 반전할지 구현 초기에 정하고 실제 기기에서 확인합니다.
- 흐림 효과는 겹친 참고 이미지에만 적용하고, 사용자 카메라와 관절 표시까지 흐려지지 않도록 렌더링 레이어를 나눕니다.
- 사용자가 올린 사진과 카메라 영상을 서버로 전송하지 않는 클라이언트 처리 방식을 우선 권장합니다. 배포 시 모델 파일 로딩 외에 이미지 업로드 요청이 없는지 확인합니다.

모델이 브라우저에서 실행되는지, 어떤 입력 모드를 지원하는지, Canvas가 기본 흐림·투명도를 제공하는지는 공식 MediaPipe 및 MDN 문서를 참고했습니다. [Canvas 필터](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/filter), [Canvas 투명도](https://developer.mozilla.org/en-US/docs/Web/API/CanvasRenderingContext2D/globalAlpha), [웹 카메라 캡처](https://developer.mozilla.org/en-US/docs/Web/API/Media_Capture_and_Streams_API/Taking_still_photos)

## 만드는 순서

아래 순서는 24시간 MVP를 처음부터 연결해 만드는 **구현 제안**입니다. 우선 웹 앱으로 설명하지만 React·Vite를 이미 쓰지 않는 팀은 익숙한 프레임워크에 같은 흐름을 적용하면 됩니다. 단계마다 먼저 가장 작은 동작을 완성한 다음 다음 단계로 넘어갑니다.

### 1단계. 앱 뼈대와 화면 상태 만들기

먼저 화면 전환과 데이터가 어디에 저장되는지 정합니다. MVP는 서버 계정 없이 한 번의 세션 안에서 진행하므로 React 상태에 참고 사진, 참고 포즈 랜드마크, 카메라 스트림, 현재 랜드마크, 촬영 결과, 보정 강도를 보관하는 구성을 권장합니다.

**화면 상태 제안**

```text
UPLOAD            참고 사진을 아직 고르지 않은 상태
ANALYZING_REFERENCE 참고 사진의 포즈를 분석 중
CAMERA_PERMISSION 카메라 권한 안내 중
COACHING          카메라 코칭 중
CAPTURED          촬영 결과 확인 중
COLOR_MATCH       참고 사진 색감 보정 미리보기 중
ERROR             사용자가 해결할 수 있는 오류 안내 중
```

**구현 순서**

1. React·Vite 프로젝트를 만들고 단일 앱 페이지를 띄웁니다.
2. 위 상태에 따라 제목, 설명, 주요 버튼이 달라지는 최소 UI를 만듭니다.
3. 아래처럼 핵심 데이터를 한 세션 상태로 정의합니다. 실제 타입명은 구현자가 정합니다.

   ```text
   referenceImage: HTMLImageElement 또는 ImageBitmap
   referenceLandmarks: PoseLandmark[] | null
   cameraStream: MediaStream | null
   currentLandmarks: PoseLandmark[] | null
   capturedImage: ImageBitmap | null
   colorMatchStrength: number (0~1)
   ```

4. 코칭 화면에서 나가거나 컴포넌트가 닫힐 때 카메라 트랙을 정지하고 객체 URL을 해제하는 정리 함수를 둡니다.
5. 이 단계에서는 모델을 연결하지 않아도 버튼을 눌러 업로드 → 코칭 → 촬영 결과 → 색감 결과 화면까지 이동할 수 있게 만듭니다.

**완료 조건:** 새로고침 후 앱이 열리고, 임시 버튼으로 전체 화면 흐름을 한 번 끝까지 이동할 수 있습니다.

### 2단계. 참고 사진 업로드 및 기준 포즈 추출

업로드 이미지는 브라우저 안에서 읽습니다. 사진 파일 자체를 화면 크기에 맞게 자르기 전에 원본 비율과 방향을 확인하고, 화면 표시용 이미지와 분석용 입력이 같은 방향을 보도록 처리합니다.

**구현 순서**

1. 파일 입력을 만들고 JPEG·PNG 등 허용할 형식을 제한합니다. 용량 상한을 둘지는 **제안 사항**이며, 큰 이미지가 느리면 긴 변을 적당한 크기로 줄인 분석용 복사본을 만듭니다.
2. `URL.createObjectURL(file)`로 미리보기 이미지를 불러옵니다. 새 사진을 선택하거나 화면을 나갈 때 `URL.revokeObjectURL()`로 이전 URL을 해제합니다.
3. 이미지 로딩이 끝난 뒤 MediaPipe Pose Landmarker를 이미지 모드로 호출해 랜드마크를 얻습니다.

   ```js
   const result = poseLandmarker.detect(referenceImage);
   const landmarks = result.landmarks?.[0];
   ```

4. 결과가 없거나 신뢰도가 낮은 필수 관절이 많으면 코칭으로 진행시키지 않고 “사람 전신이 잘 보이는 사진을 선택해 주세요” 같은 재선택 안내를 표시합니다.
5. 랜드마크가 유효하면 기준 사진과 좌표, 원본 비율을 상태에 저장합니다.
6. 사진에 사람이 여러 명 잡히는 경우는 MVP의 자동 판별 범위에서 제외합니다. 처음 해커톤 버전은 한 명이 잘 보이는 사진을 권장 입력으로 안내합니다.

**주의:** 참고 사진 위에 보이는 이미지 오버레이는 사용자가 자세와 크기를 맞추는 시각 가이드입니다. 실제 관절 비교는 사진 전체 픽셀을 겹쳐 보는 것만으로 하지 않고, 참고 사진과 카메라에서 각각 추정한 랜드마크로 수행합니다.

**완료 조건:** 적합한 참고 사진을 올리면 미리보기와 랜드마크가 준비되고, 사람이 보이지 않는 사진이면 다음 행동을 알려줍니다.

### 3단계. 카메라 미리보기와 참고 사진 오버레이

코칭 화면은 레이어를 나눕니다. 아래쪽에 카메라 영상, 위에 흐릿하고 투명한 참고 사진, 맨 위에 관절 상태 표시와 안내 문구를 둡니다. 참고 사진의 흐림이 카메라 영상이나 관절 표시까지 적용되지 않도록 참고 사진 요소에만 CSS 필터를 적용합니다.

**구현 순서**

1. 사용자가 코칭 시작을 누를 때 `navigator.mediaDevices.getUserMedia({ video: ... })`를 호출합니다. 권한은 버튼 같은 사용자 동작 직후 요청합니다.
2. 성공한 `MediaStream`을 `<video>`의 `srcObject`에 연결하고, 영상의 실제 너비와 높이가 생긴 뒤 오버레이를 그립니다.
3. 권한 거부, 카메라 없음, 보안 연결이 아닌 환경 등으로 실패하면 각각 재시도 방법을 안내합니다. 브라우저 카메라는 일반적으로 HTTPS 또는 localhost 환경이 필요합니다.
4. video와 오버레이 컨테이너를 같은 비율·같은 좌표계로 배치합니다. `object-fit: cover`를 쓴다면 잘려 나간 영역만큼 관절 좌표와 오버레이 배치도 보정해야 합니다. 구현을 단순하게 하려면 MVP에서는 `contain`으로 전체 프레임을 보이고 여백을 허용하는 방식을 먼저 검토합니다.
5. 참고 사진 `<img>` 요소에 `opacity`와 `filter: blur(...)`를 적용합니다. 초기 투명도는 사용자가 카메라 화면을 볼 수 있도록 낮게 설정하고, 불투명도 조절 UI는 시간이 허용되면 추가합니다.
6. 참고 사진을 화면 중앙에 단순히 맞추면 인물 크기와 위치가 다를 수 있습니다. 초기 버전은 사진을 프레임 안에 맞추고, 사용자가 참고 사진의 크기·위치를 조절할 수 있는 슬라이더나 드래그를 추가하는 순서를 권장합니다.
7. 앞면 카메라 미리보기 좌우 반전 여부를 결정합니다. 화면만 거울처럼 반전할지, 랜드마크 비교 좌표까지 반전할지 정하고 안내 문구의 “왼쪽/오른쪽” 기준과 일치시킵니다.

**완료 조건:** 카메라가 보이고 그 위에 참고 사진이 흐리고 반투명하게 겹칩니다. 권한 실패 시 빈 화면 대신 안내가 나옵니다.

### 4단계. 카메라 포즈 추정 및 관절 상태 표시

카메라에서 매 화면 프레임을 전부 분석하면 발열이나 화면 끊김이 생길 수 있습니다. 처음에는 새 비디오 프레임이 준비됐을 때만 추론하고, 초당 처리 횟수를 제한합니다. 실제 기기에서 느리면 프레임 간격을 늘리거나 Web Worker를 검토합니다.

**구현 순서**

1. MediaPipe Pose Landmarker를 비디오 모드로 설정합니다.
2. `requestAnimationFrame` 루프에서 video의 `currentTime`이 이전 처리 시점과 다를 때만 `detectForVideo(video, timestamp)`를 호출합니다.
3. 랜드마크의 `visibility` 또는 존재 신뢰도가 낮은 점은 “불일치”로 칠하지 않고 “비교할 수 없음”으로 둡니다. 화면 밖에 있는 관절도 같은 방식으로 제외합니다.
4. 비교할 좌우 어깨·팔꿈치·손목, 엉덩이·무릎·발목을 첫 구현 대상으로 제한합니다. 얼굴·손가락·복잡한 몸통 방향은 확장 범위입니다.
5. 화면에 그릴 때 모델의 정규화 좌표를 실제 영상 표시 영역 좌표로 바꿉니다. `contain`이면 여백 오프셋을 더하고, 미러 표시라면 x 좌표를 반전합니다.
6. 사용자 관절마다 초록색 또는 빨간색 원·선을 그립니다. 색만으로 상태를 전달하지 않도록 “맞음/조정” 범례나 짧은 안내도 함께 둡니다.
7. 관절 색이 프레임마다 깜빡이면 최근 몇 프레임의 결과를 평균내거나, 초록↔빨강 전환에 짧은 안정 구간을 둡니다.
8. 코칭 화면을 떠날 때 `requestAnimationFrame` 루프를 멈추고 MediaStream의 모든 트랙을 정지합니다.

**완료 조건:** 사람이 카메라에 들어오면 선택 관절이 표시되고, 사람이 사라지면 이전 관절 그림을 지우고 재정렬 안내를 보여줍니다.

### 5단계. 기준 포즈와 현재 포즈 비교 및 문장 코칭

두 포즈의 랜드마크를 단순히 화면 픽셀 좌표로 빼면 촬영 거리나 프레임 위치에 따라 점수가 크게 바뀝니다. MVP는 몸통 기준으로 중심과 크기를 맞춘 뒤 관절별 상대 위치를 비교하는 방식으로 시작합니다. 임계값과 점수는 **실제 기기에서 조정할 제안값**이며 보편적인 정답으로 취급하지 않습니다.

**비교 절차 제안**

1. 두 어깨와 두 엉덩이의 중점을 몸통 중심으로 계산합니다.
2. 어깨 폭 또는 어깨-엉덩이 간 거리 중 유효한 값을 기준 크기로 사용합니다.
3. 각 랜드마크에서 몸통 중심을 빼고 기준 크기로 나눠 상대 좌표를 만듭니다.
4. 참고 사진과 현재 자세의 해당 관절 상대 좌표 간 거리를 구합니다.
5. 관절별 허용 범위 안이면 초록색, 바깥이면 빨간색, 신뢰도가 낮으면 판단 보류로 표시합니다.
6. 여러 관절이 빨간색이면 가장 차이가 크고 문장 규칙이 준비된 관절 하나를 우선 안내합니다.
7. 화면 좌우 반전 때문에 좌우 관절이 맞지 않는 것처럼 보이는지 별도 확인합니다. 미러 기준이 불명확한 경우에는 좌우를 바꿔 비교해 차이가 더 작아지는 방식을 시도할 수 있지만, 시연 전 실제 샘플로 결과를 검증합니다.

**문장 생성은 규칙으로 시작합니다.** 예를 들어 오른쪽 손목이 참고 위치보다 낮으면 “오른손을 어깨 쪽으로 조금 올려 보세요”를 선택합니다. 문구 테이블은 `관절 ID + 현재 위치가 기준보다 위/아래/안/밖`을 키로 두고, 해당 규칙이 없으면 “참고 사진의 자세를 조금 더 따라 해 보세요”라는 기본 안내를 표시합니다. 외부 LLM 호출은 하지 않습니다.

**완료 조건:** 자세를 바꾸면 관절 상태와 안내 문구가 함께 바뀌고, 판단할 수 없는 관절은 잘못된 교정 안내를 하지 않습니다.

### 6단계. 촬영과 결과 이미지 만들기

촬영 사진에는 코칭 화면의 흐린 참고 사진과 초록·빨강 가이드를 합치지 않습니다. 사용자가 찍은 카메라 원본만 결과 이미지로 만들고, 참고 사진은 색감 계산을 위한 별도 기준 이미지로 보관합니다.

**구현 순서**

1. 촬영 버튼을 누르면 video의 현재 프레임을 원본 해상도에 가까운 크기의 캔버스에 그립니다.
2. 카메라가 좌우 반전되어 보였다면 최종 사진도 같은 방향으로 저장할지 결정하고, 코칭 화면과 결과 화면의 방향을 일치시킵니다.
3. 캔버스 결과를 이미지 Blob으로 변환해 `capturedImage`로 보관합니다.
4. 결과 화면에는 촬영 이미지와 다시 찍기·다음 단계 버튼을 표시합니다.
5. 재촬영 시 이전 결과와 임시 보정 결과를 정리하고 코칭 화면으로 돌아갑니다.

**완료 조건:** 촬영된 사진에 UI 오버레이가 합쳐지지 않고, 화면에서 본 방향과 결과 이미지의 방향이 일치합니다.

### 7단계. 참고 사진 색감을 촬영 사진에 적용

이번 기능의 기준은 임의의 필터 프리셋이 아니라 **사용자가 처음 올린 참고 사진**입니다. 24시간 MVP는 장면을 이해하는 전문 색보정 대신, 두 이미지의 전체 색상 통계를 이용한 가벼운 색감 이동을 제안합니다.

**Canvas 기반 MVP 절차 제안**

1. 참고 사진과 촬영 이미지를 각각 작은 분석용 캔버스에 그립니다. 분석 캔버스 크기를 제한하면 큰 원본의 픽셀을 전부 계산하지 않아도 됩니다.
2. `getImageData()`로 각 이미지 픽셀을 읽습니다. 투명 픽셀은 제외하고, 너무 어두운 픽셀이나 밝게 날아간 픽셀을 제외할지는 **조정 항목**으로 둡니다.
3. 각 채널의 평균과 표준편차 또는 평균 색상, 밝기, 채도를 계산합니다. 이 값으로 참고 사진이 상대적으로 따뜻한지·차가운지, 밝은지·어두운지의 대략적인 방향을 추정합니다.
4. 각 채널의 평균·분산 차이를 바탕으로 촬영 이미지 픽셀에 보정값을 적용합니다. 과도한 값은 0~255 범위로 제한합니다. 첫 버전에서 수식이 복잡해지면 채널별 평균 차이만 적용하는 단순한 방식으로 줄입니다.
5. 사용자가 조절하는 보정 강도 `s`를 0~1로 둡니다. 결과 픽셀은 `원본 + s × (보정 결과 - 원본)`으로 혼합해 강도를 조절합니다. `s=0`은 원본, `s=1`은 계산된 보정 결과입니다.
6. 매번 원본 촬영 이미지에서 새 결과를 계산해 보정이 누적되지 않도록 합니다.
7. 결과 화면에 원본/보정 비교와 강도 조절을 제공합니다. 보정 결과가 더 나쁘게 보이면 즉시 원본으로 돌아갈 수 있게 합니다.
8. 최종 저장은 보정된 캔버스를 Blob으로 내보냅니다. 이미지 방향, 크기, 품질을 데모 기기에서 확인합니다.

`getImageData()`에 접근할 수 없는 외부 이미지나 보안 제한이 있으면 캔버스 픽셀을 읽을 수 없을 수 있습니다. 업로드 파일을 브라우저에서 직접 읽고, 앱 출처와 다른 원격 이미지 대신 로컬 파일을 사용하면 MVP에서 이 위험을 줄일 수 있습니다. 색상 통계 방식은 배경과 피부를 구분하지 않으므로, 참고 사진과 촬영 사진의 조명·구도가 크게 다르면 부자연스러울 수 있습니다.

**완료 조건:** 같은 촬영 사진을 기준으로 보정 강도를 바꿀 수 있고, 참고 사진의 전체 색감 방향이 결과에 반영되며, 원본도 보존됩니다.

### 8단계. 통합, 오류 처리와 데모 고정

마지막에는 새 기능을 더하기보다 대표 입력으로 전체 흐름을 반복해 확인합니다. 웹 앱은 카메라가 필요하므로 배포 주소가 HTTPS인지, 모델 파일이 첫 실행 때 정상 로딩되는지도 점검합니다.

**최종 점검 순서**

1. 새로고침 후 참고 사진 업로드부터 색감 결과까지 중단 없이 진행합니다.
2. 카메라 권한을 거부하고 다시 허용하는 경우, 사진 파일이 잘못된 경우, 포즈가 검출되지 않는 경우를 각각 확인합니다.
3. 참고 사진과 카메라 영상의 좌우 방향, 인물 크기와 화면 위치를 확인합니다.
4. 조명이 다른 두세 환경에서 포즈 상태와 색감 매칭을 확인합니다.
5. 촬영·재촬영·원본 복귀를 확인하고 카메라가 화면을 나간 뒤에도 켜져 있지 않은지 확인합니다.
6. 네트워크가 불안정해도 데모할 수 있도록 모델 파일과 입력 사진을 미리 준비합니다.
7. 실제로 구현되지 않은 셀카 기능이나 고급 색보정은 시연 흐름에 넣지 않습니다.

**완료 조건:** 팀원이 같은 순서로 데모를 반복할 수 있고, 실패 상황에서도 사용자가 다음에 할 일을 안내받습니다.

## 24시간 해커톤 MVP

### MVP에 포함할 범위

- 기기에서 참고 사진 업로드
- 카메라 미리보기와 흐릿하고 반투명한 참고 사진 오버레이
- 실시간 포즈 추정 및 일부 핵심 관절의 초록색·빨간색 표시
- 상태에 따른 간단한 자연어 수정 안내
- 촬영 버튼과 촬영 결과 미리보기
- 참고 사진 색감의 간단한 자동 매칭 및 보정 강도 조절
- 결과 사진 저장 또는 공유를 위한 기본 동선

### 이번 MVP에서 제외할 범위

- 모든 포즈와 신체 동작을 지원하는 범용 분석
- 여러 사람 동시 추적, 운동 자세 안전성 진단
- 포즈 이미지 자동 검색이나 대규모 포즈 라이브러리
- 생성형 AI 기반 사진 편집 및 배경 교체
- 계정, 클라우드 갤러리, 소셜 피드
- 피부·배경을 정교하게 분리하는 전문 색보정

### 스트레치 목표

시간이 남을 때 아래 항목 중 하나를 추가로 검토합니다.

- 셀카에 적합한 상반신 포즈 가이드
- 사용자가 가진 참고 사진에서 포즈 랜드마크 추출
- 좌우 반전 카메라 화면에 대한 비교 보정
- 포즈가 충분히 맞으면 알려주는 촬영 타이머
- 사용자 피드백을 반영한 문구 개선

## 성공 기준 제안

- 처음 사용하는 사람이 참고 사진을 올리고 안내를 이해해 촬영까지 진행할 수 있다.
- 화면에서 기준 자세와 현재 자세, 초록·빨강 상태가 구분된다.
- 관절 각도 숫자 없이 다음 동작을 이해할 수 있는 문장이 나온다.
- 촬영한 사진에 참고 사진의 색감이 적용되고 보정 전·후를 비교할 수 있다.

## 저장소 시작 안내

아래 기술 조합은 현재 권장안이며 팀 합의 후 확정합니다. 최종 프레임워크와 실행·배포 절차가 정해지면 이 섹션에 설치, 실행, 모델 파일 준비 방법을 추가합니다.

## 상세 화면 및 동작 제안

다음 화면 구성은 MVP 구현을 위한 **제안**입니다. 화면 수를 줄여 하나의 페이지에서 단계별로 전환하는 방식도 가능합니다.

### 1. 참고 사진 업로드

- 서비스가 무엇을 해주는지 한 문장으로 설명합니다.
- 사용자가 기기에서 따라 하고 싶은 사진을 선택해 업로드합니다.
- 선택한 사진의 미리보기와 다시 선택할 수 있는 동작을 제공합니다.
- 업로드 후 카메라 권한을 안내하고 코칭 화면으로 이동합니다.
- 사진에서 포즈를 추정하는 과정은 MVP의 기술 검증 항목입니다. 자동 추정이 안정적이지 않으면 시연용 사진을 제한하거나 준비한 포즈 데이터와 연결하는 대안을 검토합니다.

### 2. 실시간 코칭

- 카메라 영상 위에 업로드한 참고 사진을 흐릿하고 반투명하게 겹쳐 표시합니다.
- 참고 사진과 현재 카메라 영상의 크기·위치를 사용자가 맞출 수 있도록 간단한 정렬 UI를 제공할지는 **제안 사항**입니다.
- 현재 사용자의 관절 표시를 기준과 비교해 초록색 또는 빨간색으로 강조합니다.
- 화면 상단이나 하단에는 한 번에 하나의 수정 안내를 우선 노출합니다.
- 좌우 방향 혼란을 줄이기 위해 “화면 왼쪽”인지 “내 왼쪽”인지 표현 기준을 정하고, 안내 문구를 일관되게 유지합니다.
- 프레임 처리 중, 카메라 권한 거부, 사람 미검출 상태에 대한 안내를 마련합니다.
- 사용자가 코칭을 건너뛰고 직접 촬영할 수 있는 경로를 둘지 여부는 **제안 사항**입니다.

### 3. 촬영 및 결과

- 촬영 전 셀프 타이머를 제공할지는 **선택 사항**이며, 기본 MVP에서는 촬영 버튼을 우선합니다.
- 촬영 후 원본과 선택된 보정 결과를 미리 볼 수 있습니다.
- 참고 사진의 색감을 적용한 결과를 미리 보고 보정 강도를 조절하거나 원본으로 되돌릴 수 있습니다.
- 저장 또는 공유 버튼을 제공하되, 플랫폼이 확정되기 전까지 구체적인 저장 API는 미정입니다.

## 포즈 비교 로직 초안

다음은 이해를 돕기 위한 **제안 로직**입니다. 정확한 좌표 처리와 임계값은 선택한 플랫폼과 모델 출력에 맞춰 조정해야 합니다.

1. 기준 이미지 또는 포즈 데이터와 카메라 프레임에서 신체 랜드마크를 얻습니다.
2. 랜드마크의 신뢰도가 낮거나 화면 밖에 있는 관절은 비교 대상에서 잠시 제외합니다.
3. 좌표를 몸통 크기 등 기준 길이로 정규화해 카메라 거리 차이의 영향을 줄입니다.
4. 좌우 어깨·팔꿈치·손목, 엉덩이·무릎·발목처럼 MVP에 필요한 관절만 비교합니다.
5. 관절별 차이가 허용 범위 안이면 초록색, 범위를 벗어나면 빨간색으로 표시합니다.
6. 빨간 관절 중 사용자가 가장 먼저 고치면 좋은 항목 하나를 골라 안내 문장을 보여줍니다.

한 프레임의 흔들림으로 색이 계속 바뀌지 않도록 최근 프레임을 부드럽게 반영하거나, 상태 변경에 약간의 안정 구간을 두는 방안을 검토합니다. 화면 좌우 반전, 신체 크기 차이, 가려진 관절에 대한 처리는 기술 검증이 필요한 항목입니다.

### 자연어 안내 규칙 예시

| 감지한 차이 | 사용자 안내 예시 |
| --- | --- |
| 오른쪽 손목이 기준보다 낮음 | 오른손을 어깨 쪽으로 조금 올려 보세요. |
| 왼쪽 팔이 몸에 너무 가까움 | 왼팔을 몸 바깥쪽으로 조금 벌려 보세요. |
| 무릎 위치가 기준보다 안쪽임 | 무릎을 발끝 방향으로 조금 열어 보세요. |
| 관절이 화면에서 확인되지 않음 | 전신이 화면 안에 들어오도록 한 걸음 물러나 보세요. |
| 여러 관절이 기준에 가까움 | 좋아요, 거의 맞았어요. 잠시 그대로 있어 보세요. |

문구는 사용자를 평가하거나 탓하는 표현을 피하고, 가능한 한 구체적인 행동 하나를 제시합니다. 예시 문구는 최종 UX 문구가 아닌 초안입니다.

## 색감 보정 동작 제안

- 보정은 원본 파일을 덮어쓰지 않고 별도의 미리보기 결과로 적용합니다.
- 업로드한 참고 사진을 색감의 기준으로 사용합니다.
- MVP에서는 두 사진의 밝기, 채널별 평균색, 채도 차이를 계산해 촬영 사진에 보정값을 적용하는 방안을 제안합니다.
- 사용자가 보정 강도를 낮추거나 높일 수 있게 하고, 원본과 결과를 나란히 비교할 수 있도록 합니다.
- 여러 번 선택해도 원본 기준으로 계산해 보정이 누적되지 않도록 합니다.
- 출력 이미지의 방향 정보, 가로세로 비율, 품질 저하 여부를 실제 기기에서 확인합니다.
- 구체적인 색 공간과 저장 품질은 이미지 처리 라이브러리 및 플랫폼 결정 후 확정합니다.

### 통합·제품·보정

- 관절 상태에서 안내 문구를 고르는 규칙 구현

- 프론트엔드와 비전 모듈 간 데이터 계약 정리
- 대표 시나리오에 맞춰 오류 및 빈 상태 문구 준비
- 데모 진행 순서와 발표 자료 구성

세 역할은 고정된 담당 경계가 아니라 작업 시작을 위한 **제안**입니다. 팀원 간 중복 작업을 줄이도록 초기에 화면 크기, 좌표계, 좌우 방향, 상태 데이터 형태를 합의합니다.

구체적인 타입은 플랫폼 선택 후 확정하되, 모듈 간에는 다음과 같은 정보를 주고받는 방안을 제안합니다.

1. 사용자가 따라 하고 싶은 참고 사진을 업로드하고 미리보기를 확인합니다.
2. 카메라를 켜고 참고 사진을 흐릿하고 반투명하게 겹쳐 보며 화면에서 몸의 위치를 맞춥니다.
3. 현재 자세의 일부 관절이 빨간색으로 표시되고, 참고 사진과 비교해 차이가 보이는 모습을 보여줍니다.
4. “오른손을 어깨 쪽으로 조금 올려 보세요”라는 안내에 따라 자세를 바꾸면 해당 관절이 초록색으로 전환됩니다.
5. 포즈가 충분히 맞으면 촬영하고 결과 화면으로 이동합니다.
6. 참고 사진의 색감을 촬영 결과에 적용하고, 보정 전·후를 비교한 뒤 저장 흐름을 보여줍니다.

데모는 실제 구현된 기능만 사용합니다. 셀카 확장이나 자동 포즈 추출이 완성되지 않았다면 향후 확장으로 소개합니다.

## MVP 완료 기준 상세안

- [ ] 사용자가 참고 사진을 업로드할 수 있다.
- [ ] 사용자가 참고 사진을 업로드하고 미리 볼 수 있다.
- [ ] 카메라 화면에 흐릿하고 반투명한 참고 사진이 겹쳐 보인다.
- [ ] 사용자 관절 상태가 초록색 또는 빨간색으로 구분된다.
- [ ] 각도 수치 없이 수정 행동을 설명하는 문구가 표시된다.
- [ ] 카메라나 인식이 준비되지 않았을 때 사용자가 다음 행동을 알 수 있다.
- [ ] 사진을 촬영하고 촬영 결과 화면으로 이동할 수 있다.
- [ ] 촬영 후 참고 사진의 색감을 적용해 보고 원본과 비교하거나 되돌릴 수 있다.
- [ ] 팀원이 정한 대표 데모 흐름을 연속으로 시연할 수 있다.

완료 기준은 **기획 제안**이며, 24시간 내 구현 가능성을 확인하면서 우선순위를 조정합니다.
